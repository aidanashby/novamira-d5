Tested on Divi 5.15.1 (14 October 2026): a template built in the Theme Builder, then its header and footer layouts edited through PHP and checked in a browser. Template creation on a fresh site rechecked on 5.16.0 (21 October 2026). Load `divi5-core` first; layouts use the same block format and recipes.

## How Divi stores Theme Builder data

- One `et_theme_builder` post (status publish) lists its templates in repeated meta `_et_template` (template post IDs).
- Each template is an `et_template` post. Meta: `_et_default` (`1` for the Default Website Template), `_et_enabled`, `_et_use_on` and `_et_exclude_from` (assignment rules, for example `singular:post_type:page:id:55`), and `_et_header_layout_id`, `_et_body_layout_id`, `_et_footer_layout_id` with matching `_enabled` flags. A layout ID of `0` means the theme default.
- Each layout is an `et_header_layout`, `et_body_layout` or `et_footer_layout` post whose `post_content` is normal Divi 5 block markup (placeholder, section, row, column, modules) with the usual builder meta.

Read the whole picture first:

```php
$tb_id = et_theme_builder_get_theme_builder_post_id(true, false); // 0 when the Theme Builder was never used
$out = [];
foreach ($tb_id ? get_post_meta($tb_id, '_et_template') : [] as $tid) {
    $m = get_post_meta($tid);
    $out[] = ['id' => $tid, 'title' => get_the_title($tid), 'use_on' => $m['_et_use_on'] ?? [],
              'header' => $m['_et_header_layout_id'][0] ?? '0', 'body' => $m['_et_body_layout_id'][0] ?? '0',
              'footer' => $m['_et_footer_layout_id'][0] ?? '0'];
}
return $out;
```

## Edit a layout

1. Find the layout ID from its template. Say which pages the template applies to (`_et_use_on`) before editing: a layout edit goes live at once on every page it is assigned to, because layouts are published posts (verified: the edit showed on the live page straight away).
2. Ask the user before editing a layout used site-wide (the Default Website Template, or broad rules such as all pages), unless they already asked for that change.
3. Save the current `post_content` (return it, so it can be restored), then parse, modify and serialise exactly as for a page, and write it with `wp_update_post` and `wp_slash()`.
4. Call `ET_Core_PageResource::remove_static_resources($layout_id, 'all')`, and the same for a page that uses the template.
5. Check in a browser: the header is `.et-l--header`, the footer `.et-l--footer`, a body layout's content inside `.et-l--body` (that class also wraps ordinary pages, so look for the layout's own content). Check one page the template should affect and one it should not.

## Create a template for a post type (verified with Movies)

Use Divi's own functions. Check first that no template already covers the same assignment, and record the Theme Builder post's current `_et_template` list for undo. A site where the Theme Builder was never used has no Theme Builder post: `et_theme_builder_get_theme_builder_post_id(true, true)` returns the published one, or creates it only when none exists (verified on 5.16.0); log it as created by you. `et_theme_builder_insert_layout()` publishes the layout, sets its `layout_type` term and enables the builder (verified on 5.16.0).

```php
$theme_builder_id = et_theme_builder_get_theme_builder_post_id(true, true);
$lid = et_theme_builder_insert_layout(['post_type' => 'et_body_layout',
    'post_title' => 'Movies single body', 'post_content' => wp_slash($content)]);
if (is_wp_error($lid)) return $lid->get_error_message();
update_post_meta($lid, '_et_pb_use_divi_5', 'on');
update_post_meta($lid, '_et_pb_show_page_creation', 'off');
$tid = et_theme_builder_store_template($theme_builder_id, ['title' => 'All Movies', 'autogenerated_title' => '0',
    'default' => '0', 'enabled' => '1', 'use_on' => ['singular:post_type:movie:all'], 'exclude_from' => [],
    'layouts' => ['header' => ['id' => 0, 'enabled' => true], 'body' => ['id' => $lid, 'enabled' => true],
                  'footer' => ['id' => 0, 'enabled' => true]]], false);
add_post_meta($theme_builder_id, '_et_template', $tid);
```

- Assignment strings: list every valid one with `et_theme_builder_get_template_settings_options()` (collect each `id`). For a post type: `singular:post_type:<type>:all` (all single posts, verified), `singular:post_type:<type>:id:<ID>` (one post), `archive:post_type:<type>` (the post type archive, verified with `/movies/`; the type needs Has archive on).
- An archive body uses a loop (see `divi5-dynamic`, with pagination) where a single body uses current-post values.
- Header or footer `0` means the global or theme default. Only published layouts are accepted.
- Build the body with current-post dynamic values (`divi5-dynamic`) and a `divi/post-content` module for the post's own content.
- Clear caches for posts of that type with `remove_static_resources`, then check one post of the type and one page that must not change. `.et-l--body` also appears on ordinary pages, so check for the template's own content, not that class.
- Undo: delete the template and layout posts and remove the template ID from the Theme Builder post's `_et_template` meta.

## A page without the default title bar

When a page should open straight under the header with its own heading as the H1 (a campaign or landing page), it needs a template of its own (`singular:post_type:page:id:<ID>`) whose body layout is `0`, so only the page's content shows between header and footer. Check first whether that page already has one; if so, change only `_et_body_layout_id` to `0` and record the old value for undo (verified on 5.16.0). The page must then carry its own `h1`. Ask before creating a new template.

## Do not, unless the user asks

Create or delete templates, change `_et_use_on` or `_et_exclude_from`, change which layouts a template points to, or edit the `et_theme_builder` post. These change which pages get which header and footer across the site. When the user asks, use the recipe above rather than writing the meta by hand.
